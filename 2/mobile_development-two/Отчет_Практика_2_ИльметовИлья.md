## Введение

Ключевым компонентом визуального интерфейса в Android-приложениях является **Activity** (активность) — обычно ассоциируется с отдельным экраном приложения. Переключение между экранами происходит через переход от одной активности к другой.

Учёт размера экрана устройства — важный фактор. Для решения проблемы размещения всех элементов интерфейса используются:

- Диалоговые окна, уведомления, всплывающие подсказки (простой способ, не требует изменений в манифесте).
- Несколько `Activity` в одном приложении (универсально, но не всегда оптимально по производительности).
- Переключение между частями интерфейса на одной активности.
- Собственные экраны, отображаемые на `Activity` в зависимости от состояния.

**Цель практики:** Изучить инструменты отладки, жизненный цикл `Activity`, создание и вызов активностей, работу с диалоговыми окнами.

### 1.2 Инструментарий просмотра отладочных сообщений (LogCat)

Класс `android.util.Log` позволяет выводить сообщения разных уровней:

- `Log.e` — ошибка
- `Log.w` — предупреждение
- `Log.i` — информация
- `Log.d` — отладка
- `Log.v` — verbose
- `Log.wtf` — What a Terrible Failure

Пример:
```java
private static final String TAG = MainActivity.class.getSimpleName();
Log.d(TAG, "Мой код выполняется!"); 
```

## Глава 2. Жизненный цикл Activity

Создание классического мобильного приложения требует наличия одного или нескольких компонентов **Activity**. Как правило, работа приложения начинается с класса `MainActivity`:

```java
public class MainActivity extends AppCompatActivity {
    // ...
}
```
Все активности представляют собой объекты класса android.app.Activity, который содержит базовую функциональность. В примере MainActivity наследуется от AppCompatActivity, который в свою очередь наследуется от базового класса Activity.
Приложения для ОС Android имеют строго определённый системой жизненный цикл. При запуске пользователем приложения операционная система создаёт отдельный процесс. Это позволяет определять различный приоритет процессов. Благодаря этому входящие звонки не блокируются при работе с приложениями. После прекращения работы пользователя с приложением производится высвобождение ресурсов и снижение приоритета процесса.
## 2.1 Методы жизненного цикла «Activity»
Запуск мобильного приложения приводит к вызову первого экрана — Activity. Запуск проходит через ряд событий, для обработки которых существуют следующие обратные вызовы (callback-методы): 
```java
Javaprotected void onCreate(Bundle savedInstanceState);
protected void onStart();
protected void onRestoreInstanceState(Bundle savedInstanceState);
protected void onRestart();
protected void onResume();
protected void onPause();
protected void onSaveInstanceState(Bundle savedInstanceState);
protected void onStop();
protected void onDestroy();
```

## 2.2 Создание активности
Метод onCreate(Bundle savedInstanceState) — первый метод, с которого начинается выполнение активности.
В этом методе:

Выполняется первоначальная настройка экрана;
Вызывается setContentView(R.layout.activity_main) для привязки XML-разметки;
Инициализируются элементы интерфейса через findViewById().

Объект Bundle может содержать ранее сохранённое состояние активности. При первом запуске он равен null.
## 2.3 Основные методы подготовки отображения активности
Перед отображением графического интерфейса пользователю вызываются следующие методы:
```java
onStart() — подготовка к выводу активности на экран. Графический интерфейс уже создан, но ещё не виден пользователю.
onResume() — переводит активность в состояние Resumed. Активность получает фокус и становится доступной для взаимодействия с пользователем. Здесь рекомендуется выполнять лёгкие операции.
onPause() — вызывается, когда активность теряет фокус (например, при переходе в другую активность или выключении экрана). Здесь следует освобождать ресурсы (камеру, аудио, анимации).
onStop() — активность больше не видна пользователю. Здесь можно сохранять данные.
onDestroy() — вызывается перед уничтожением активности.
onRestart() — вызывается перед onStart(), если активность возвращается после остановки.
onSaveInstanceState(Bundle outState) — сохранение динамического состояния (не всегда вызывается, например, при нажатии «Назад»).
onRestoreInstanceState(Bundle savedInstanceState) — восстановление сохранённого состояния.
```


Пример кода:
Java@Override
protected void onResume() {
    super.onResume();
    Log.i(TAG, "onResume()");
    // Инициализация камеры после получения фокуса
}

@Override
protected void onPause() {
    super.onPause();
    Log.i(TAG, "onPause()");
    // Освобождение ресурсов
}

@Override
protected void onSaveInstanceState(Bundle outState) {
    super.onSaveInstanceState(outState);
    outState.putString("key", "value");
}
